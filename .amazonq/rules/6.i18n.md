# HomeLedger - Internationalization (i18n)

Configuration de l'internationalisation avec next-intl pour Next.js 15 App Router.

## 🌍 Langues Supportées

- **Anglais** (en) - Langue par défaut
- **Français** (fr)

## 📁 Structure

```
i18n/
├── request.ts      # Configuration next-intl
└── routing.ts      # Définition des locales et navigation

messages/
├── en.json         # Traductions anglaises
└── fr.json         # Traductions françaises

app/
└── [locale]/       # Routes avec support i18n
    ├── layout.tsx  # Layout avec NextIntlClientProvider
    └── page.tsx    # Pages traduites
```

## 🔧 Configuration

### Middleware
Le middleware (`middleware.ts`) détecte automatiquement la langue du navigateur et redirige vers la bonne locale.

### Routing
- Locale par défaut (en) : `/` ou `/en`
- Autres locales : `/fr`
- Configuration : `localePrefix: "as-needed"` (pas de préfixe pour la langue par défaut)

## 💻 Utilisation

### Dans les Server Components

```tsx
import { useTranslations } from "next-intl";

export default function MyPage() {
  const t = useTranslations("common");
  
  return <h1>{t("welcome")}</h1>;
}
```

### Dans les Client Components

```tsx
"use client";

import { useTranslations } from "next-intl";

export default function MyComponent() {
  const t = useTranslations("navigation");
  
  return <nav>{t("dashboard")}</nav>;
}
```

### Navigation avec i18n

```tsx
import { Link, redirect, useRouter } from "@/i18n/routing";

// Link component (préserve la locale)
<Link href="/dashboard">Dashboard</Link>

// Changer de locale
<Link href="/dashboard" locale="fr">Tableau de bord</Link>

// Redirection serveur
redirect("/login");

// Navigation client
const router = useRouter();
router.push("/settings");
```

### Composant Language Switcher

Utiliser `<LanguageSwitcher />` pour permettre aux utilisateurs de changer de langue.

```tsx
import { LanguageSwitcher } from "@/components/language-switcher";

<LanguageSwitcher />
```

## 📝 Structure des Traductions

Les fichiers JSON sont organisés par namespace :

```json
{
  "common": {
    "appName": "HomeLedger",
    "welcome": "Welcome"
  },
  "navigation": {
    "dashboard": "Dashboard"
  },
  "auth": {
    "login": "Log in"
  }
}
```

## ✅ Bonnes Pratiques

1. **Toujours utiliser les traductions** : Pas de texte en dur dans les composants
2. **Namespaces logiques** : Grouper les traductions par domaine (common, auth, transactions, etc.)
3. **Navigation i18n** : Utiliser `Link` et `useRouter` de `@/i18n/routing` au lieu de `next/link`
4. **Types** : TypeScript infère automatiquement les clés de traduction disponibles
5. **Ajout de langues** : 
   - Ajouter la locale dans `i18n/routing.ts`
   - Créer le fichier `messages/{locale}.json`
   - Mettre à jour le `LanguageSwitcher`

## 🔄 Workflow d'Ajout de Traductions

1. Ajouter les clés dans `messages/en.json`
2. Traduire dans `messages/fr.json`
3. Utiliser dans les composants avec `useTranslations()`

## 🚫 À Éviter

- ❌ Utiliser `next/link` directement (utiliser `@/i18n/routing` à la place)
- ❌ Texte en dur dans les composants
- ❌ Oublier de traduire les métadonnées (title, description)
- ❌ Mélanger les namespaces (garder une organisation cohérente)
