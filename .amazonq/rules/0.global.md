# HomeLedger - 2026 Tech Stack & Engineering Standards

You are a Senior Fullstack Expert. Your mission is to build HomeLedger, a high-performance personal finance manager, using a modern Node.js/TypeScript ecosystem.

## 🛠 Core Tech Stack

- **Framework**: Next.js 15+ (App Router).
- **React**: Server Components (RSC) by default.
- **Compiler**: React Compiler enabled. (Strictly avoid `useMemo`, `useCallback`, or `memo` unless technically essential).
- **Styling**: Tailwind CSS + shadcn/ui (Radix UI primitives).
- **Database**: PostgreSQL + Drizzle ORM.
- **Auth**: Auth.js (v5) - OIDC via Keycloak (Vendor-agnostic).
- **Validation**: Zod (Mandatory for Server Actions and Schema definitions).
- **Logging**: Pino (Structured JSON logging).

## 🏗 Architectural Principles

1. **Server-First**: Prioritize React Server Components. Use `"use client"` only for interactivity (forms, modals).
2. **Data Flow**: Use **Server Actions** for all internal mutations. No internal `/api/*` routes.
3. **Database Integrity**: Single source of truth in `/db/schema.ts`. Automated SQL migrations via `drizzle-kit`.
4. **Security**: Validate every input with Zod. Verify sessions via `auth()` in every Action.
5. **Types**: Strict TypeScript. No `any`. Use `infer` from Zod for shared types.

## 📁 File Structure & Naming

- **Components**: PascalCase (`TransactionCard.tsx`).
- **Server Actions/Libs**: kebab-case (`create-transaction.ts`).
- **Styles**: Use shadcn CSS variables (`hsl(var(--primary))`).
- **Organization**:
  - `/app`: Routing & Layouts.
  - `/db`: Schema & Client config.
  - `/lib/actions`: Business logic (Mutations).
  - `/components/ui`: Atomic shadcn components.

## ⌨️ CLI & Workflow Reference

You must use these commands for development and maintenance:

### 1. Database Management (Drizzle)

- **Generate SQL Migration**: `npx drizzle-kit generate`
- **Push Migration to DB**: `npx drizzle-kit migrate`
- **Database GUI (Studio)**: `npx drizzle-kit studio`
- **Introspect (Pull from existing DB)**: `npx drizzle-kit introspect`

### 2. Infrastructure (Docker)

- **Start Services**: `docker-compose up -d` (Postgres + Keycloak).
- **Stop Services**: `docker-compose down`.

### 3. UI Components (shadcn)

- **Add Component**: `npx shadcn@latest add [component-name]`

### 4. Quality Control

- **Format Code**: `npx prettier --write .` (Uses `prettier-plugin-tailwindcss`).
- **Type Check**: `npx tsc --noEmit`.

### 5.directives

- **Documentation**: all functionnal descriptions must be documented in readme.md

### 6. POC
Le répertoire /poc/ contient la V1 de HomeLedger (Express/React SPA). Il sert de spécification technique et fonctionnelle vivante pour la reconstruction vers la stack 2026.

Structure du POC :

/poc/homeledger-api : Logique métier Node.js/Express, schémas de données initiaux et endpoints.

/poc/homeledger-front : Composants React client-side, UI/UX de référence et intégration OIDC.

Directives pour Kiro :

Analyse Comparative : Avant de créer une nouvelle fonctionnalité, analyse systématiquement le code correspondant dans /poc/ pour en extraire les règles métier, la charte graphique et le workflow utilisateur.

Transposition Intelligente : Ne copie pas le code. Traduis la logique Express en Server Actions et les composants React SPA en React Server Components (RSC).

Data Mapping : Utilise les modèles de données du POC pour définir les nouveaux schémas Drizzle ORM dans /src/db/schema.ts, en les optimisant pour PostgreSQL.

Style & UI : Reproduis la charte graphique présente dans le POC en utilisant exclusivement Tailwind CSS et les primitives de shadcn/ui.

Authentification : Utilise le flux OIDC identifié dans le POC pour configurer Auth.js (v5), en veillant à ce que l'implémentation reste agnostique de Keycloak.
